# Contributing

Contributions are welcome if they keep the project generic, practical, and safe for public use.

## Guidelines

- Keep examples vendor-neutral when possible.
- Do not include private workspace names, private paths, secrets, or unpublished assets.
- Prefer short templates over complex frameworks.
- Add documentation for any new workflow rule.
- Keep the protocol usable by a fresh agent with no chat history.

## Development

This repository has no build step.

Before opening a pull request:

```bash
git status --short
```

Review all changed files manually.
